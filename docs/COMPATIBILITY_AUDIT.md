# BrowserOxide: проверка совместимости и достоверности метрик

Проверено 5 сентября 2026 года на macOS arm64. Рабочая копия:
`905ea68d05fdf2f17fd5ffc54d09007e74f45b0f` плюс существовавшие незакоммиченные
изменения пользователя. Это выборочный аудит текущей сборки, не сертификация
браузера и не оценка вероятности прохождения антибот-защиты.

**Вывод: работающий движок есть; универсальная эффективность stealth не доказана.**
Исполнение JavaScript, изменения DOM, простой layout и рисование действительно
работают. Однако даже небольшая независимая проверка обычных Web API выявила
четыре нарушения поведения. Основная опубликованная метрика успеха не проверяет
завершение пользовательского сценария и может засчитать пустую страницу.

**Прямое локальное сравнение.** Одна и та же
[страница](../tools/compatibility_probe.html) выполнена в трёх движках.
Chrome и Camoufox запускались headless в новых контекстах через установленный
Playwright; у Camoufox отключены дополнения и GeoIP. Сторонние сайты в этом
сравнении не использовались.

| Движок | Путь выполнения | Совпало с ожидаемым поведением |
|---|---|---:|
| Google Chrome 152.0.7977.76 | Загрузка страницы с локального HTTP-сервера | 11/11 |
| Camoufox 152.0.4-beta.29 | Та же страница с того же сервера | 11/11 |
| BrowserOxide, release, default features | `PagePool::acquire` → `reload_html` → event loop | 7/11 |

Для BrowserOxide использован встроенный preset `chrome_148_macos`.
`reload_html` загружает документ в уже созданный runtime. Это не полный путь
`navigate_warm_with_init`: загрузка ресурсов и жизненный цикл навигации этим
способом не проверяются. Страница содержит только inline-код и не требует
внешних ресурсов. Поэтому сравнение относится к выполненным операциям Web API.

| Сценарий | Chrome и Camoufox | BrowserOxide |
|---|---|---|
| Перемещение существующего DOM-узла между родителями | `[0,1,true]` | Совпало |
| Вставка DocumentFragment опустошает фрагмент | `[0,2,"ab"]` | Совпало |
| Сохранённая `children` обновляется после вставки; `querySelectorAll` остаётся снимком | `[2,1]` | **`[1,1]`** |
| Отмена события через `preventDefault` | `[false,true]` | Совпало |
| `once` вызывается один раз; слушатель с отменённым `signal` не вызывается | `[1,0]` | **`[1,2]`** |
| `MutationObserver` передаёт предыдущие значения атрибута | `[null,"one"]` | **`[null,null]`** |
| Сброс формы восстанавливает значение | `["initial","initial"]` | Совпало |
| Изменения `URL.searchParams` и `URL.search` синхронизированы | `["?q=a+b&x=1","two",false]` | **`["?q=a%20b","a b",true]`** |
| Ширина CSS content-box с padding и border | `["40px",54]` | Совпало |
| Canvas 2D рисует и возвращает красный пиксель | `[255,0,0,255]` | Совпало |
| Promise-microtask выполняется перед timer-task | `["sync","microtask","timer"]` | Совпало |

Ожидания для коллекций, событий и MutationObserver сверены с
[DOM Standard](https://dom.spec.whatwg.org/#interface-htmlcollection),
[обработкой signal у слушателя](https://dom.spec.whatwg.org/#add-an-event-listener)
и [MutationRecord.oldValue](https://dom.spec.whatwg.org/#dom-mutationrecord-oldvalue).
Связь URL и параметров определена
[URL Standard](https://url.spec.whatwg.org/#urlsearchparams-update).
Это функциональные требования, а не предположения о сигналах конкретного детектора.

Подтверждённые области исходников: `Element.children` в
`dom_bootstrap.js:1087`, регистрация слушателя в `event_bootstrap.js:450`,
записи и доставка MutationObserver в `dom_bootstrap.js:3750`, реализация URL в
`window_bootstrap.js:5250` и URLSearchParams в `shared_apis_bootstrap.js:257`.
Семантика живых коллекций важна для динамических интерфейсов; отмена слушателей —
для удаления обработчиков; oldValue — для обработки изменений; связь URL и
параметров — для корректного построения адресов. Никакой связи этих четырёх
результатов с решением Epic/Talon здесь не установлено.

**Отдельный воспроизводимый дефект HTTP.** Обычная навигация devview на
`http://127.0.0.1:18763/compatibility_probe.html` завершилась
`TLS handshake failed [WRONG_VERSION_NUMBER]`. На сервере были попытки TLS
handshake вместо HTTP. Chrome и Camoufox эту страницу загрузили.
`HttpClient::get_with_headers` (`src/net/mod.rs:852`) выбирает TLS/H2 и TLS/H1
без отдельного пути для схемы `http`, а порт по умолчанию — 443. Аналогичная
структура есть в `get_with_exact_headers`. Это объясняет наблюдавшийся сбой;
исправление только номера порта не устранило бы использование TLS для HTTP.

**Главный риск оценки качества — ложный критерий успеха.**
`engine_classify` (`src/classify.rs:228`) получает только строку HTML,
проверяет подстроки и длину. Он не видит успешного действия пользователя,
выполнения обработчика, результата операции или видимости интерфейса.
`sweep_metrics` (`examples/sweep_metrics.rs:261`) считает успехом
`tag == "L3-RENDERED" && len >= 15000`.

Два локальных входа через свежесобранный `classify_stdin` дали:

```text
Пустая страница с 16000 символами в HTML-комментарии:
L3-RENDERED  16048

Короткая страница с заголовком Done и текстом завершённой операции:
THIN-BODY    92
```

Первый вход проходит и критерий sweep, и `ChallengeVerdict::Pass`, хотя не
содержит видимого содержимого. Второй считается незавершённым рендером.
Это доказывает наличие ложных результатов у критерия; это не измерение числа
ошибок в историческом корпусе из 126 сайтов. Дополнительно критерии расходятся
на диапазоне 15000–15359 байт: sweep использует 15000, а `verdict_for` —
`15 * 1024` (`src/classify.rs:46,207`).

**Заявления в документации требуют повторной верификации.**

- README сообщает routed 118/126, а `docs/BENCHMARK.md` — 119/126. Последний
  описывает запуск от 2026-06-05 на deno_core 0.403; текущий Cargo.toml
  использует 0.408. Исторические результаты не проверяют текущую рабочую копию.
- Best-of-four — объединение лучших исходов четырёх профилей. Без заранее
  зафиксированного выбора и независимого повторного прогона это результат
  выбора после измерения, а не вероятность успеха одного нового запуска.
- Сохранённых сырых JSON/CSV результатов именно этих исторических запусков в
  текущем репозитории не найдено. Есть код сетевых проверок и сохранённый
  Chrome 147 fixture, но они не заменяют результаты заявленного запуска.
- `sweep_metrics::self_rss_mb` (`examples/sweep_metrics.rs:92`) читает
  Linux `/proc/self/statm`, предполагает страницу памяти 4 KiB и возвращает
  0 при ошибке. На этом macOS он не измеряет память. `rss_peak_mb` в этом
  примере — максимум снимков после страниц, не обязательно настоящий пик.
  В `docs/MEMORY.md` описан другой Linux-замер через VmHWM. Коэффициент 15×
  здесь заново не измерялся и этим аудитом не подтверждён и не опровергнут.
- Описания реализации устарели: README говорит о deno_core 0.403 и tiny-skia,
  в текущем Cargo.toml — deno_core 0.408 и skia-safe 0.99.

**Что ценно в существующей работе.** Это реальный отдельный движок с V8,
DOM, layout, Canvas и сетевым кодом. Использование готовых html5ever, taffy,
Skia и BoringSSL — нормальная инженерная опора. В репозитории есть проверки
совместимости и зафиксированные данные Chrome 147; доказательной базы не ноль.
Однако наличие API, совпадение отдельных значений и отсутствие Chromium сами
по себе не доказывают полную браузерную совместимость. Web API в том числе
реализованы собственными JS bootstrap-слоями (`src/js_runtime/runtime.rs:345`),
которые также требуют проверки поведения.

**Практическая оценка.** Разумно считать BrowserOxide исследовательским
движком с работающими частями и существенными пробелами. Считать его уже
доказанным эквивалентом Chrome/Camoufox по совместимости или stealth оснований
нет. 7/11 — результат одиннадцати выбранных сценариев, не «64% совместимости».
Для следующего этапа полезнее исправить подтверждённые ошибки Web API и HTTP,
а успех прикладных сценариев определять по их результату. Точные вероятности
нужно получать повторными измерениями с заранее заданным критерием; они не
следуют из числа свойств или объёма HTML.

**Воспроизведение.** Из корня репозитория:

```bash
cargo run --offline --release -p browser_oxide --example compatibility_probe -- tools/compatibility_probe.html
```

Для эталонного браузера открыть ту же HTML-страницу через локальный сервер:

```bash
python3 -m http.server 18763 --bind 127.0.0.1 --directory tools
```

Адрес: `http://127.0.0.1:18763/compatibility_probe.html`. JSON отображается
на странице. В Camoufox читать результат из DOM (`#output`): доступность
переменной страницы из изолированного контекста автоматизации не предполагается.
Пример печатает JSON даже при несовпадениях; оценивать поле `passed` и строки
`pass: false`, а не только код завершения процесса.

В ходе аудита прошли release-сборки devview, classify_stdin и нового примера,
`cargo fmt --all -- --check`, `cargo clippy --offline --all-targets --workspace -- -D warnings`.
Существующие тестовые наборы не запускались. Изменений реализации движка в
этом аудите нет: добавлены этот отчёт, HTML-проба и запускающий её пример.
